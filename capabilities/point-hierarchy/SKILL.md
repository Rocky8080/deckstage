# 观点层级审查（Point Hierarchy）

> 一句话：**一页只许有一个观点；每个模块都必须认领一句观点；没人认领的模块就是多余的。**

因果链（`causal-value-chain`）解决「这个观点能不能被反驳」，设计质量（`design-quality`）解决「这页读不读得清」。
本技能解决中间那一层：**这页到底在说什么，以及每块内容凭什么留在这儿。**

---

## 1. 什么时候用

- 一页里塞了 4 张卡、5 个步骤，说不出「所以这页要我相信什么」
- 两个模块讲的是同一件事，只是换个说法（最常见：方案页和价值页）
- 同一句话在相邻两页各讲一遍
- 想从「一堆素材」往上提炼出一级级观点（汇报、复盘、方案、路演）

---

## 2. 四层观点金字塔

```
L0  全册主张   ← 一句话，全册服务它（通常在目录页给出）
L1  章节主题   ← 一章（一个实践 / 一个论点），有自己的结论句
L2  页面断言   ← 每页标题 = 一句能被反驳的话；一页只承载一个 L2
L3  模块论据   ← 页面里的每块（卡片 / 步骤 / 图 / 引文 / 表）认领 L2 的一个侧面
L4  证据       ← 数字 / 截图 / 记录 / 原文引述，支撑 L3
```

**链条必须单向**：L4 支撑 L3，L3 支撑 L2，L2 支撑 L1，L1 支撑 L0。
任何一层说不清「我支撑上面哪一句」，就在那一层出问题——不要往下补内容，要往上找句子。

---

## 2.5 页间接力：上一页留下什么，下一页接住什么

四层金字塔是**包含关系**（L3 支撑 L2、L2 支撑 L1），它回答「这页每块内容凭什么留在这儿」，
但它**不回答「这一页凭什么排在上一页后面」**。一套 deck 最常见的两种病，一种在包含层（重复、孤儿），
另一种在接力层——**上一页已经收口，下一页另起一个话题**，读者会觉得「怎么突然跳到这儿」。

所以每两页之间要能回答一句话：

> **上一页结束时的未答问题是什么？这一页的开头（标题或第一块）是不是在回答/追问它？**

三种合法接法：

| 接法 | 长什么样 | 例子 |
|---|---|---|
| **承接**（顺着说） | 下一页标题与上一页结论共用实词 | 「六份文件收进一个入口」→「一个入口里放什么」 |
| **转折**（反问） | 标题里有转折/追问词：但 / 不够 / 还差 / 除了 / 否则 / 反过来 | 「交付解决了」→「一个展示系统，不够」 |
| **显式过渡句** | 在上一页或下一页写一句 `bridge`：「闭环能跑之后，下一个问题是…」 | 作品页之间最常见的写法 |

**都不是，就是断链。** 判断方法：把一章所有页面标题连成一句话读——
读出来是并列（问题 / 交付 / 写作能力），就是断的；读出来是递进（问题 / 交付 / 但还不够 / 写作），才成立。

> 修法只有两种：**换标题**（把新话题改成对上一页的追问），或**补一句桥**（在上一页结尾留一个问题）。

## 2.6 展示程度：一页放多少才算「够」

「主/次」解决的是**权重**，「展示程度」解决的是**体积**。两者都不对，页面就是「讲得挺全，但记不住」。

| 位置 | 上限 | 超出怎么办 |
|---|---|---|
| 页面断言 | 1 句 | 第二个观点 → 拆页，或降成第一句的从句 |
| 论据块 | ≤ 3 块 | 第 4 块开始，先问「它改变读者相信什么？」——不改变就下沉讲稿 |
| 每块论据 | 1 句解释 + 1 个证据 | 解释写成两句，就是没想清楚；证据超过 2 个，挑最强的 |
| 单页可见字数 | ≤ 520 字（经验值） | 超了先删解释，不要缩字号 |
| 实现细节 | 只在「这一页就是讲实现」时才上页 | 名字 + 一句话规则；参数、路径、命令进讲稿 |

**下沉而不是删除**：讲稿（`<aside class="notes">`）是这些细节的家。「何时用 / 边界 / 例外 / 参数」写进讲稿，
现场被问到再展开；页面上只留让人记住的那一句。

## 3. 每个模块先回答三个问题

| # | 问题 | 答不出来的后果 |
|---|---|---|
| Q1 | 这个模块**支撑哪一句**（页面断言里的哪个词/哪个从句）？ | 孤儿模块 → 删 / 移到别的页 / 提升为独立页 |
| Q2 | 有没有**另一个模块在说同一件事**？ | 重复 → 合并，或一个为主一个降为次 |
| Q3 | 在支撑同一句的模块里，它是**主还是次**？ | 无主次 → 并列疲劳，读者记不住哪个是重点 |

### 三种处理动作

| 判定 | 条件 | 动作 |
|---|---|---|
| **保留为主** | 支撑页面断言的核心从句，且是唯一或最强的证据 | 给最大字号 / 最大面积 / 唯一强调色 |
| **降为次** | 支撑同一句的补充面，或只回答「还有哪些」 | 降一级字号、去强调色、压成一行 |
| **合并** | 两个模块相似度 ≥ 0.5（说的是同一件事） | 合成一块，保留信息量更大的那个 |
| **分类说明** | 3 个以上模块并列、彼此不重复、各自是不同侧面 | **不要硬合并**：加分类标签（谁 / 何时 / 哪类），并指定主次 |
| **附件** | 不支撑任何观点，只服务现场操作（入口 / 二维码 / 快捷键说明） | 允许存在，但必须压到视觉最低、不占论据位 |
| **语境** | 交代背景（一次跑动包含哪些环节），不是证据也不是论据 | 最多一行；讲稿里要点明「这只是交代环节，证据在别处」 |
| **删 / 移页** | 与页面断言无关键词交集，且不是附件也不是语境 | 删；若是别的论点的主证据则移页 |

> 「分类说明」是最容易被忽略的一档：**并列不等于重复**。三个侧面各有各的证据时必须分类，硬合并会把可核对的信息压成口号。

## 4. 可机器检查的规则

| 规则 | 判定 | 级别 |
|---|---|---|
| H1 **标题是断言** | 标题是问句/话题（为什么要做 / 如何…），或是名词短语黑名单（核心功能 / 使用说明 / 成果 / 价值 / 背景 / 概述 / 介绍）且 ≤12 字 → 不合格 | P1 |
| H2 **模块认领** | 模块与「标题 + 结论句」没有共同实词 → 孤儿模块候选 | P2 |
| H3 **同页重复** | 同页两个模块相似度 ≥ 0.60 → 必须合并 | **P0** |
| H4 **跨页重复** | 同一章节内、不同页的模块相似度 ≥ 0.55 → 同一观点讲了两遍（合并成页，或降级为一句） | P1 |
| H5 **并列无主次** | 同页模块 ≥5 → 需人工确认是否分主次 / 是否该分类说明 | P2 |
| H6 **断言无证据** | 标题是数值型断言（含 → / 倍 / % / 天 / 小时 / 屏 / 人）但页面既无数字也无图/表/记录 | P1 |
| H7 **数字无口径** | 页面出现数字，但没有「口径 / 基准 / 同一套 / 相比 / 分母」之类 | P1 |
| H8 **章节缺结论页** | 同一 `data-rail` 章节里没有一页承担结论（kicker 含「成果 / 结论 / 方案与成果」） | P2 |
| H9 **承接断点** | 同一章节内，上一页结论句与本页标题既无共同实词、标题也没有转折词（但/不够/还差/除了/其实/所以/接下来…） | P2 |
| H10 **细节过载** | 单页可见字数 > 520（经验值）→ 把不影响「相信」的解释下沉讲稿 | P2 |

相似度口径：中文按**二元组 Dice**（去标点、去停用词「实践人 / 方案与成果 / 所以 / 我把」等），英文按词。

### 工具的实现取舍（与上表的差异，全部写进 `--help`）

- **H1 只判「问句 / 话题 / 短名词」**，不猜「长标题有没有谓语」——猜不准，宁可漏。
- **H2 只给 P2 候选，并加三道减误报**：页面没有结论句不判；与同页其它模块有共同实词按「侧面」不判；模块 < 12 字不判。
- **H4（跨页重复）跳过封面与收尾**：导览卡、致谢语天然相似，不是「讲了两遍」。
- **H7 / H8 对说明型 deck 跳过**（含「问题 / 方案 / 成果 / 实践 / 复盘」语义的 kicker 少于 2 屏或不足 20%）：说明文档的数字是操作参数，不是断言。
- **已知盲区**：`li` 列表、纯 `span` 步骤（`flow` 除外）、记录行 `div`、入口条这类「非卡片」结构不算模块，统计会偏低——这类页面必须人看。
- **包裹层下钻**：命中容器里若还套 ≥2 个同类容器，会再下钻一层（否则三张卡会被合成一个模块）。
- **H9 只查词面与转折词**：判断不了论证是否真的成立；上一页写了 `.bridge` 过渡句的不判（作者已把接力写出来），
  上一页没有结论句、结论句短于 24 字、或本页是全册最后一屏（收尾页）时也不判。
- **H10 是经验阈值**：两套校准 deck 平均 273 / 352 字，最密的两页 516 / 1187 字；只提示，不阻断。

## 5. 交付格式：观点地图

改一屏或审一册，都按这个格式交付：

**写之前先填两行**（填不出来就别开始排模块）：

```
这页回答上一页提出的哪个问题：<一句话>
看完这页，对方会问什么：<一句话>
```

审完或写完，按「观点地图」交付：

```
L0 全册主张：<一句话>
L1 章节：<实践 / 论点> —— 结论句：<可反驳的一句>
  L2 页：<第 N 页> 断言：<标题原文>
     L3 模块 ①：<模块名> —— 支撑断言里的「<关键词>」—— 主 / 次 —— 证据：<数字或图>
     L3 模块 ②：<模块名> —— 与 ① 重复（相似度 0.62）→ 合并
     L3 模块 ③：<模块名> —— 孤儿（与断言无交集）→ 删 / 移页
  处理：<保留 / 降级 / 合并 / 分类说明 / 删>，改动后这页的一句话观点是：<一句>
```

**审完必须回答的三个问题**

1. 这册有几个观点？比屏数少多少？（观点数 ≈ 章节数，不是屏数）
2. 有多少模块是孤儿、重复？（两者相加应低于模块总数的 15%）
3. 每个章节是否都有一页承担「结果」？没有的那一章，是不是本来就没有结果（那就明说没有，别补口号）。

## 6. 自检 12 问

1. 这页标题是一句能被反驳的话，还是一个名词？（名词就是没观点）
2. 这页有几个观点？超过一个就拆或降级。
3. 每个模块能指认它支撑标题里的哪个词吗？
4. 有没有两个模块在说同一件事？
5. 支撑同一句的几个模块，哪个是主？（字号/面积/颜色只许一个赢）
6. 三个以上并列的模块，是重复还是不同侧面？（不同侧面要分类，不要合并）
7. 这句断言有证据吗？证据是数字、截图还是原文引述？
8. 数字有口径吗？和谁比、分母是什么？
9. 这页的观点和相邻页重复吗？（方案页与价值页最常见的重复）
10. 这一章有没有一页承担「结果」？没有的话，是不是本来就还没有结果？
11. **这一页接得住上一页吗？** 上一页留下的未答问题，本页开头有没有回答或追问？
12. **这一页是不是讲得太全了？** 字数超 520、论据超过 3 块、每块解释超过一句，就先删再加。

## 7. 工具

```bash
python3 tools/hierarchy.py outline "src-<名>/slides/*.html"   # 每页：断言 + 模块清单 + 相似度矩阵
python3 tools/hierarchy.py audit   "src-<名>/slides/*.html"   # H1–H10，P0/P1/P2（--json 机器可读）
python3 tools/hierarchy.py map     "src-<名>/slides/*.html"   # 全册观点地图 + 跨页重复对
```

- `P0` 必须为 0（同页高度重复的模块）；`P1` 要逐条解释为什么保留。
- 构建（`node build.mjs`）会跑同一套检查：P0 直接失败，P1/P2 打印提示。
- 工具只做**结构**判断；主次、分类、是否值得讲，仍然要人读一遍。

## 8. 与其他两份能力的分工

| 层 | 归属 | 一句话 |
|---|---|---|
| 有没有观点 / 是不是一个观点 | **本技能** | 一页一断言，模块认领制 |
| 观点能不能被反驳 / 有没有数字 | `causal-value-chain` | 数字三件套、一把尺子、反事实 |
| 读不读得清 / 页与页长得是否重复 | `design-quality` | 对比度、强调色面积、骨架多样性 |

三者的关系：**先有观点（本技能）→ 观点要能被反驳（因果链）→ 然后才谈好看（设计质量）**。
顺序反过来，就是把没有观点的页面排得很好看。
