# 观点层级审查能力

一页只许有一个观点；每个模块都必须认领一句观点；没人认领的模块就是多余的。
本能力管的是中间那一层：**这页到底在说什么，以及每块内容凭什么留在这儿。**
方法与规则见 [SKILL.md](SKILL.md)，可直接复制的审查提示词见 [prompts/audit-deck.md](prompts/audit-deck.md)。

因果链（[causal-value-chain](../causal-value-chain/SKILL.md)）解决「这个观点能不能被反驳」，
设计质量（[design-quality](../design-quality/SKILL.md)）解决「这页读不读得清」；
本能力解决「先有没有观点、一页是不是只有一个观点」。

## 解决什么问题

- 一页里塞了 4 张卡、5 个步骤，说不出「所以这页要我相信什么」
- 两个模块讲同一件事，只是换个说法（最常见：方案页和价值页）
- 同一句话在相邻两页各讲一遍
- 想从「一堆素材」往上提炼出一级级观点（汇报、复盘、方案、路演）

## 四层观点金字塔

```text
L0  全册主张   ← 一句话，全册服务它（通常在目录页给出）
L1  章节主题   ← 一章（一个实践 / 一个论点），有自己的结论句
L2  页面断言   ← 每页标题 = 一句能被反驳的话；一页只承载一个 L2
L3  模块论据   ← 页面里的每块（卡片 / 步骤 / 图 / 引文 / 表）认领 L2 的一个侧面
L4  证据       ← 数字 / 截图 / 记录 / 原文引述，支撑 L3
```

链条必须单向：L4 支撑 L3，L3 支撑 L2，L2 支撑 L1，L1 支撑 L0。
任何一层说不清「我支撑上面哪一句」，就在那一层出问题——不要往下补内容，要往上找句子。

## 三层规则

| 层 | 要回答的问题 | 不合格怎么办 |
|---|---|---|
| **页面层** | 标题是一句能被反驳的断言，还是名词？（H1）断言有证据、数字有口径吗？（H6 / H7）接得住上一页吗，是不是讲得太全？（H9 / H10） | 把名词标题改写成断言；补证据或口径，缺数据写 `【需补：<哪个数>】`；换标题或在上一页补一句过渡；超字先删解释，不缩字号 |
| **模块层** | 每个模块支撑断言里的哪个词？有没有另一块在说同一件事？支撑同一句时谁是主？（H2–H5） | 孤儿模块删 / 移页；同页高度重复合并；并列的不同侧面加分类标签并指定主次 |
| **章节层** | 这一章有一页承担「结果 / 结论」吗？（H8） | 补结论页；确实还没有结果就明说，别补口号 |

H1–H10 的判定条件与 P0/P1/P2 级别见 [SKILL.md §4](SKILL.md)；P0 必须为 0。

### 处理动作

| 判定 | 动作 |
|---|---|
| 保留为主 | 给最大字号 / 最大面积 / 唯一强调色 |
| 降为次 | 降一级字号、去强调色、压成一行 |
| 合并 | 两块说的是同一件事时合成一块，保留信息量更大的那个 |
| 分类说明 | 3 个以上并列且各是不同侧面：加分类标签（谁 / 何时 / 哪类）并指定主次，不要硬合并 |
| 删 / 移页 | 与页面断言无交集的孤儿模块（附件、语境不算，判定见 [SKILL.md §3](SKILL.md)） |

「并列不等于重复」：三个侧面各有证据时必须分类，硬合并会把可核对的信息压成口号。

## 怎么用

```bash
python3 tools/hierarchy.py outline "src-<名>/slides/*.html"   # 每页：断言 + 模块清单 + 相似度
python3 tools/hierarchy.py audit   "src-<名>/slides/*.html"   # H1–H10，P0/P1/P2（--json 机器可读）
python3 tools/hierarchy.py map     "src-<名>/slides/*.html"   # 全册观点地图 + 跨页重复对
```

- `P0` 必须为 0（同页高度重复的模块）；`P1` 要逐条解释为什么保留。
- 工具只做**结构**判断；主次、分类、是否值得讲，仍然要人读一遍。

审完按「观点地图」交付（完整格式见 [SKILL.md §5](SKILL.md)）：

```text
L0 全册主张：<一句话>
L1 章节：<实践 / 论点> —— 结论句：<可反驳的一句>
  L2 页：<第 N 页> 断言：<标题原文>
     L3 模块 ①：<模块名> —— 支撑断言里的「<关键词>」—— 主 / 次 —— 证据：<数字或图>
     处理：<保留 / 降级 / 合并 / 分类说明 / 删>，改后这页的一句话观点是：<一句>
```

写或改完一屏，再用 [SKILL.md §6 的自检 12 问](SKILL.md) 过一遍。

## 和另外两套能力的分工

| 层 | 归属 | 一句话 |
|---|---|---|
| 有没有观点 / 是不是一个观点 | **本技能** | 一页一断言，模块认领制 |
| 观点能不能被反驳 / 有没有数字 | `causal-value-chain` | 数字三件套、一把尺子、反事实 |
| 读不读得清 / 页与页长得是否重复 | `design-quality` | 对比度、强调色面积、骨架多样性 |

顺序：**先有观点（本能力）→ 观点要能被反驳（因果链）→ 然后才谈好看（设计质量）**。
顺序反过来，就是把没有观点的页面排得很好看。

## 安装与使用

仓库内的 `AGENTS.md` 与构建检查随代码提供。`./install.sh` 会把本能力与 `causal-value-chain`、
`design-quality` 三套技能装进本机**已检测到的所有 AI 客户端**，并把用户级「观点层级纪律」
并入各客户端的规则文件；客户端目录与生效方式见
[因果链 / 价值链能力包的安装说明](../causal-value-chain/README.md#安装与使用)。

```bash
./install.sh --check                                                   # 按客户端列出缺什么 / 哪个是旧版本
python3 tools/install_capability.py --agents codex,workbuddy --user    # 只装指定客户端（all=全部）
python3 tools/install_capability.py --workspace <目录>                  # 把写作与结构规则并入该工作区 AGENTS.md
```

## 构建时检查

```bash
node build.mjs --src src-sample --deck sample-deck
```

构建会跑同一套结构检查：同页高度重复等 P0 问题会阻断构建，P1/P2 只提示。
表达（`frame`）与视觉（`design_audit`）检查照旧。
