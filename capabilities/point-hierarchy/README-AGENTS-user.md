## 观点层级纪律

写或改幻灯片 / 汇报 / 方案时，先定观点、再排内容——不需要用户点名，也不依赖 skill 加载。因果链管「观点能不能被反驳」，设计质量管「这页读不读得清」，这份纪律管「这页到底在说什么、和上一页接不接得上」。

1. **一页一断言**：每页标题是一句能被反驳的话，不是名词短语；「核心功能 / 概述 / 价值 / 背景」这类标题不算观点，一页只承载一个观点。
2. **模块认领**：页面里每块内容（卡片 / 步骤 / 图 / 表 / 引文）都要认领一句——它支撑标题里的哪个词；认不出来就是孤儿模块 → 删掉或移到别的页。
3. **重复必合并**：同页两块说同一件事 → 合并成一块；相邻两页讲同一件事 → 合成一页，或把其中一处降成一句。
4. **接得住上一页**：每页开头要回答或追问上一页留下的问题——标题共用实词（承接）、或带转折词（但 / 不够 / 还差 / 除了 / 反过来）、或在上一页写一句过渡句。三条都没有就是断链：换标题，或补桥。
5. **并列要分类 + 主次**：三块以上并列时先判断是重复还是不同侧面——不同侧面加分类标签，不要硬合并；支撑同一句的模块只许一个「主」。
6. **一页别放太多**：论据 ≤ 3 块、每块 1 句解释 + 1 个证据、可见字数 ≤ 520；「何时用 / 边界 / 参数」写进讲稿，现场被问再展开。
7. **每章要有结论页**：每个章节（一个实践 / 一个论点）至少一页承担「结果 / 结论」；确实还没有结果就明说，不要用口号补。
8. **写之前先填两行**：这页回答上一页提出的哪个问题？看完这页，对方会问什么？——填不出来就别开始排模块。
9. **有工具就用工具**：本仓库有 `tools/hierarchy.py` 时，先跑 `python3 tools/hierarchy.py audit "<路径>"`，**P0 必须为 0**；H9（承接断点）/ H10（细节过载）是 P2 候选，逐条确认。`outline` 看每页断言与模块清单，`map` 看全册观点地图。

工具只做结构判断；主次、分类、接得接不住、值不值得讲，仍要人读一遍。审完按「观点地图」交付：L0 全册主张 → L1 章节结论 → L2 页面断言 → L3 模块（主 / 次 + 证据）。
