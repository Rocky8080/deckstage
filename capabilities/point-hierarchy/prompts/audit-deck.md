# 提示词：审查一份 PPT / 文档的结构

你可以直接复制下面这段给 Codex / ZCode / DSH（把 `<路径>` 换成实际文件或目录）：

---

请用「观点层级」框架审查 `<路径>` 里的每一屏 / 每一节，按严重度排序输出。

步骤：
1. 先运行 `python3 tools/hierarchy.py audit "<路径>" --json`，拿到规则级问题；再跑
   `outline "<路径>"` 与 `map "<路径>"`，拿到每页断言、模块清单和跨页重复对。
2. 对每一屏回答：
   - 这页的一句话观点是什么？标题是断言还是名词？
   - 每个模块支撑标题里的哪个词？有没有孤儿模块？
   - 有没有两个模块在说同一件事（同页 / 跨页）？
   - 支撑同一句的模块，哪个是主、哪个是次？
   - 三个以上并列的模块，是重复还是不同侧面？（不同侧面要分类，不要硬合并）
   - 这句断言有证据吗？数字有口径吗？
   - 这一章有没有一页承担「结果 / 结论」？
   - 这一页接得住上一页吗？上一页留下的未答问题，本页开头有没有回答或追问？
   - 这一页是不是讲得太全了？字数超 520、论据超过 3 块，就先删再加。
3. 输出观点地图 + 修改表：`屏 | 现在的说法 | 问题（H2 孤儿 / H3 重复 / …）| 建议改法（给可直接粘贴的文案）| 优先级 P0/P1/P2`。
4. 不要编造数字；缺数据就写「需要你提供：<具体是哪个数>」。

约束：
- 一页只留一个观点；模块只留能被认领的。
- 重复就合并；并列的不同侧面要分类并指定主次，不要为了统一格式硬合并。
- 给建议时必须说明这页改完的一句话观点是什么。
